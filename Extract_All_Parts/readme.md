# Inventor iLogic - Structured BOM to Excel Extractor (Individual Occurrences)

This iLogic script for Autodesk Inventor allows you to completely and recursively export a structured list of all parts and subassemblies from an assembly file (`.iam`). 

Unlike traditional Inventor Bills of Materials (BOM) that group components by part number, **this script extracts each occurrence (instance) individually**. This means it explicitly separates every single element generated by **Patterns** and **Mirrors**.

## 📋 Features and Extracted Columns

The script generates a Microsoft Excel file (`.xlsx`) in the same directory where the main assembly is saved. It organizes components with a unique sequential ID and maps the exact genealogy of each part:

* **ID:** Unique, incremental sequential number.
* **PART (OCCURRENCE):** Unique instance name in the model browser (e.g., `Bolt:1`, `Bolt:2`, `Mirror_Bracket:1`).
* **PARENT ASSEMBLY:** The immediate subassembly containing the component.
* **GRANDPARENT ASSEMBLY:** The second-level parent assembly in the hierarchical chain (useful for mapping dependencies in complex structures).
* **PART NUMBER:** Native file iProperty (`Part Number`).
* **MATERIAL:** Physical property assigned to the component (automatically detects if it's an assembly or a part).
* **MASS (kg):** Actual physical mass calculated individually in kilograms.
* **DESCRIPTION:** Native file iProperty (`Description`).
* **FULL PATH:** Exact location on the hard drive or local server (`FullFileName`).

## 🛠️ Environment Requirements

* **Autodesk Inventor** (Any version with iLogic support).
* **Microsoft Excel** physically installed on the same machine (the script uses background OLE/COM automation).
* The assembly (`.iam`) must be saved to disk before running the rule to define the output path for the Excel file.

## 🚀 Installation and Usage

1. Open your main assembly (`.iam`) in Autodesk Inventor.
2. Open the iLogic panel (**Manage** tab -> **iLogic** panel -> **iLogic Browser**).
3. Right-click in an empty area of the *Rules* tab and select **Add Rule**.
4. Name the rule `BOM_export` (or your preferred name).
5. Paste the provided code into the iLogic editor.
6. Click **Save & Run**.
7. The script will run in the background (Excel will remain hidden to improve processing speed). Upon completion, a dialog box will appear confirming the path of the generated file.

## 🔍 Algorithm Details (Handling Patterns and Mirrors)

The code uses a **recursive** function that interacts with the Inventor API's `ComponentOccurrences` collection. 

When Inventor creates a pattern (e.g., an array of 4 bolts) or a mirror, the software doesn't create new files on the disk; instead, it instantiates multiple occurrences in the 3D space. By iterating through the `.SubOccurrences` property of each object, the script forces a detailed read of these virtual sub-patterns, successfully listing them as individual rows in the spreadsheet.

Additionally, the script implements a **Stack** data structure using a .NET `List(Of String)` to track the assembly tree's genealogy in real-time. This allows it to identify the Parent and Grandparent with absolute precision, regardless of how many levels deep the part is located within subassemblies.

## ⚠️ Exception Handling

* **Virtual Parts / Broken Links:** The script includes `Try...Catch` blocks that prevent the rule from crashing if it encounters virtual components (parts without a physical file that only hold properties, like grease or gaskets) or broken OLE links.
* **Open Files:** If the target Excel file already exists and is currently open by the user, the script will throw a controlled alert message (`Save Error`) requesting to close the file to prevent data loss.
* **Suppressed Components:** By design, the script automatically skips any component that is currently in a *Suppressed* state within the active Level of Detail / Model State representation.
